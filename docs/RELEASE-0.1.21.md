# dsh-pre-duediligence 0.1.21

Version: **0.1.21**
Date: **2026-09-13**

## 本次修复

- 资料采集和证据核验页新增持续可见的执行卡：展示当前查询维度、真实查询数、已闭环数、无数据、无需执行、待处理、失败、最近完成项和累计耗时。
- 工具调用之间的模型研判阶段明确显示“本轮查询已返回，正在研判与整理”；报告整理阶段明确显示“正在生成一页纸报告”，不再长时间保持静态页面。
- Host 运行记录按业务维度采用最新结果。实际完成、无数据或无需执行会覆盖此前的合成待处理记录，避免已闭环步骤仍显示黄色。
- 顶部流程的“待复核”使用中性色，与真正的风险关注黄色分离；红线、关注、信息和明确未发现仍使用各自业务语义色。
- 八项经营状态明确为互斥研判结果；当前项、非当前项、未形成结论和待研判都有文字状态，不再只靠颜色传意。

## 验证与边界

- Node 24.18.0 下严格类型检查、22 个测试文件 / 161 项测试、Host/Client 构建、浅色/深色 × 桌面/窄屏 4 个隔离 Chrome 场景及 npm 包清单 dry-run 通过。
- 实时卡显示的是 Host 已记录的真实事件数量与耗时，不估算完成百分比；模型研判本身没有可验证的细粒度百分比。
- `done / no-data / skipped` 为绿色闭环；`unknown / no-permission / not-executed` 保留待处理含义；查询失败为红色。流程待复核本身不等于企业风险预警。
- 经营状态八选一，未选中的七项是“非当前研判”，不是七次未执行的数据查询；采集覆盖以上方“采集结果”为准。
- 自动化使用合成 Host / Provider 记录；生产账号的实际耗时和数据结果仍受 Connector、OAuth、产品权限、Provider 额度及限流影响。

## 升级

```sh
dsh plugin --profile web add dsh-pre-duediligence@0.1.21
```

安装后完整停止并重启对应 DSH Web Profile。Better Sidebar 仍为可选工作台；stable 与 candidate 必须使用 README 列出的成套版本。
