# 继续尽调与报告版本（一期）

历史详情填写补充要求，点击「创建补充任务」。任务提交后在当前专属 Session 中由 `previsit_continue` 创建新任务；基于旧任务已确认主体，无需重新搜索。原工作区之外的续办会拒绝，不隐式跨工作区迁移资料。

## 版本与证据

- 未带新字段的历史报告视为 V1，无需重写旧记录。
- 新任务保存 rootTaskId、parentTaskId、reportVersion、supplementIntent 和历史证据快照及日期。
- 同一报告系列版本号单调分配，允许基于较早版本分支。处理中占用版本号，不能因失败复用编号。
- 每个任务有独立查询进度、用量和报告。继承证据不计本次查询；风险/人员刷新仍走原核验约束。
- 原报告不可覆盖；相同内容重复 finalize 幂等，不同内容必须另建版本。并发 finalize 串行防覆盖。
- 新任务 requestId 稳定；重复续办不重复建任务。新 Session 可在同工作区续办。`previsit_history` 用于对话中查找报告，再明确基础版本与补充要求。
- 只补查经营等非核验维度时沿用基线；历史核验资料缺失或基线为 partial 时，新报告不能被当作完整重新核验通过。

## 操作与边界

历史详情展示同系列版本入口、基础任务和补充要求。下载文件包含版本号与任务标识。报告内容仍为完整八段，并由模型在覆盖说明记录基线日期和本次增量。

本期不包含新闻舆情 Provider 新接口、本地材料抽取、网页下载、双源冲突引擎、PDF/Word 或上传交付；没有接入的维度需明确告知，不能以模型知识冒充实时查询。

验证包括旧报告不变、并发分支版本、幂等与冲突、跨工作区拒绝、重启恢复、继续后定向查询与新版本保存。真实 DSH 操作验收和发布单独执行。
