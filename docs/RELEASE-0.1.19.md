# dsh-pre-duediligence 0.1.19

Version: **0.1.19**
Date: **2026-09-12**

## 本次修复

- “拜访客户”改为插件 Session Store 内的隔离草稿，逐字输入和中文输入法选词不再写入或聚焦原生会话；普通 Enter 也不会启动任务，只有点击“开始尽调”才提交完整快照。
- 移除 fast / standard / deep 的 8 / 18 / 40 次插件硬上限；档位只控制覆盖优先级和目标深度，旧活动任务读取时自动迁移为不限次。
- 风险扫描零计数的八类明细逐项记录“无需执行”；非零明细必须实际下钻。关键人员无数据时董监高扫描明确跳过，有人员时必须执行。
- 显式完成工具与 UI 报告回写共用同一核验完成门，避免报告已生成但明细下钻、董监高和任务历史仍未闭环。
- 资料采集和证据核验子项按真实结果显示运行中、完成、无需执行、待核验或失败状态，并保留原因。

## 验证与边界

- Node 24 下严格类型检查、22 个测试文件 / 153 项测试及 Host/Client 构建通过。
- 浅色/深色 × 桌面/窄屏共 4 个真实 Chrome 隔离场景通过，连续输入“苏州”到“苏州恒琪”时原生草稿写入与会话发送均为 0，焦点保持在侧栏输入框。
- 测试使用合成 Host / Provider 记录，未配置生产模型或企查查 OAuth，未消耗真实企查查额度。
- 插件不设调用次数上限；Provider 自身的账户额度、产品权限和限流仍按真实返回生效。

## 升级

```sh
dsh plugin --profile web add dsh-pre-duediligence@0.1.19
```

安装后完整停止并重启对应 DSH Web Profile。Better Sidebar 仍为可选工作台；stable 与 candidate 必须使用 README 列出的成套版本。
