# v0.3.4 变更：修复下载报告抓错内容

## 问题
v0.3.3 的「下载报告」能点了，但下载出来的是会话里注入的系统提醒/技能清单（<system-reminder>…），不是作战卡。
原因：提取器按"最后一次工具事件之后的助手文本"拼接，而 DSH 会话在重启后会把技能清单作为一个节点注入，
其 role/kind 字段不在顶层，过滤不掉；且它恰好含"覆盖"等关键词。

## 修复
- 改为"按内容定位"：从末尾找最后一个含作战卡起点（`# 拜访作战卡 · 企业名` 或 `## ① 核心研判`）的节点，
  从起点切片到节点末尾（前面的过程性文字不进报告），只拼接紧邻的 Markdown 延续节点。
- 硬性排除含 <system-reminder> / <available_skills> 等注入标记的节点。
- 结构校验：必须同时含"核心研判"和"现场必问/覆盖说明"才算作战卡。
- 新增 2 个单测（切片、注入排除），共 29 个通过。

## 应用
同前：覆盖 skills/ 与 lib/，Ctrl+C 后重新 dsh web，刷新浏览器。
验证：grep "version:" ~/qcc-previsit-dsh/skills/qcc-previsit-onepager/SKILL.md → version: 0.3.4
下载后文件名应为「拜访作战卡_企查查科技股份有限公司.html」（不再是"拜访作战卡_拜访作战卡"）。
